# 층별 이동 제한과 점유 존

[FMS 안내](../fms_server/README.md) · [승강기](elevators.md) · [개발 구조](architecture.md)

교차로·좁은 통로처럼 충돌 위험이 있는 곳을 점유 존으로 지정해 한 대씩 통과시킨다.
층별 제한은 **한 맵에서 동시에 이동 허가를 보유할 수 있는 로봇 수**다.
맵 하나를 물리 층 하나로 운영한다. 한 층을 여러 맵으로 나눈 경우 그 맵들의 정원을 합산하지 않는다.

## 웹에서 설정

1. 상단에서 현장과 맵을 선택한다.
2. **현장 설정 → 선택 맵 교통 제어**에서 동시 이동 허가 대수를 입력하고 적용한다.
   빈칸은 무제한이다. 기본값도 무제한이다.
3. 실시간 맵에서 방향별 **대기 node와 출구 node를 먼저 목적지로 등록**한다.
4. **＋ → 구역 → 점유 존**을 선택해 사각형을 그리고 **진입 방향 추가**로 대기·출구 쌍을 지정한다.
5. 저장하면 새 맵 버전을 전달한다. 모든 로봇의 맵 동기화·위치 확인 후 작업을 배정한다.

존 위쪽 원형 핸들 또는 **구역 회전(°)** 입력으로 중심 기준 회전이 가능하다.
회전한 실제 경계를 기준으로 겹침·진입 차단·차체 이탈을 판단한다. 대기·출구 node는 함께 회전하지 않는다.

선택한 목적지 좌표를 점유 존의 맵 버전에 **복사**한다. 이후 원래 목적지를 이동·삭제해도
존의 node는 바뀌지 않는다. node를 바꾸려면 점유 존을 다시 편집한다.
존 없이 대수 제한만 사용하거나, 대수 제한 없이 점유 존만 사용할 수도 있다.
구형 클라이언트는 점유 존 맵의 작업 배정이 거절된다. FMS와 C++ 클라이언트를 함께 갱신한다.

## node와 존 배치

- 위험한 교차 공간 전체를 존 안에 넣는다. 서로 비켜갈 수 없는 통로는 통로 전체를 하나의 존으로 잡는다.
- 대기·출구는 맵 안의 FREE 위치에 두고 존과 충분히 떨어뜨린다.
  실행 시 로봇 외접원 반지름 `hypot(width, length)/2 + 0.1 m`의 여유를 검사한다.
- 양방향이면 방향마다 대기·출구 쌍을 만든다. 대기 node가 반대편 로봇의 퇴장 경로를 막지 않도록 대기 공간을 마련한다.
- 한 대기 node에는 한 대만 접근시킨다. 후속 로봇은 출발 위치 또는 이전 허가 지점에서 기다린다.
- 존 내부와 차체 여유 경계에는 작업 시작점·목적지를 둘 수 없다. 장기 주차·충전·작업 지점은 존 밖에 둔다.
- 겹치거나 경계를 공유하는 점유 존은 웹 등록 시 거절한다. 서로 너무 가까워 node의 차체 여유가 부족한 경우에도 경로를 만들 수 없다.
- 승강기 칸·도킹 설비와 직선 진입/후진 구간은 점유 존과 분리한다. 미허가 존을 지나는 직선 동작은 로봇이 오류로 차단한다.

FMS는 grid에서 모든 점유 존을 막은 외부 구간과, 지정한 gate의 존 통과 구간을 연결해 경로를 고른다.
존을 지나지 않는 경로가 더 짧으면 그 경로를 사용한다. 로봇은 각 구간의 허가 조건을 유지하며 실제 A* 경로를 계산한다.

## 이동 허가와 점유 해제

1. 층별 이동 허가를 확보한다. 정원이 차면 오더의 노드를 미허가 상태로 보내 현재 위치에서 대기시킨다.
2. 대기 node를 예약한 뒤 그 node까지 허가한다. 다른 로봇의 현재 위치와 예약된 대기·출구의 차체 여유도 검사한다.
3. 대기 node 도착과 정지를 확인한다. 존이 비어 있고 출구 공간도 비어 있으면 존을 예약하고 출구까지 허가한다.
4. 출구 node 통과와 차체 전체의 존 이탈을 확인하면 점유를 해제한다. 다음 외부 구간이나 다음 존의 대기 node까지 진행한다.
5. 오더 종료 후 로봇의 정지와 IDLE/CHARGING 보고를 확인하면 층별 이동 허가를 반납한다.

허가 가능한 작업은 전송 시각·작업 ID 순서로 검사한다. 대기 node에 아직 도착하지 않은 로봇이
이미 도착한 다른 방향의 진입을 막지는 않는다. 대기·출구 node는 작업 진행률에 포함하지 않는다.

층별 정원은 속도가 아니라 **허가 보유 대수**로 센다. 실행 중 일시정지·존 대기·액션 수행 중에는
허가를 유지한다. 작업 없는 주차·충전 로봇은 제외한다. 제한을 낮춰도 기존 허가를 회수하지 않고 신규 허가부터 막는다.
다층 작업은 승강기를 잡기 전에 도착 층 정원을 예약한다. 자리가 없으면 탑승 전 승강장 위치에서 기다린다.

## 상태와 장애 처리

현장 설정에는 이동 허가·대기 node 예약·존 예약과 대기 이유를 표시한다.
실시간 맵에는 대기·출구와 존 상태를 표시하고, 작업 게시판의 **대기·오류**에도 대기 이유를 표시한다.

| 존 상태 | 의미 |
|---|---|
| 비어 있음 | 확인되지 않은 점유나 예약이 없음 |
| 진입 예약 | 한 로봇에 진입을 허가함 |
| 점유 중 | 예약 로봇의 차체가 존에 걸쳐 있음 |
| 확인 필요 | 미허가 점유, 통신 두절, 위치 확인 상실 또는 등록 로봇의 상태 미수신 |

같은 맵의 다른 로봇 상태가 불명확하면 신규 진입을 보류한다. 사용하지 않는 등록 로봇도 확인 대상이다.
전원을 끈 로봇을 단순히 비어 있다고 판단하지 않는다.

취소·오류·통신 두절은 퇴장 증거가 아니다. **예약에 TTL을 두지 않으며 서버 재시작 후에도 유지**한다.
취소된 로봇이 존 안에 있으면 계속 막는다. 로봇을 안전하게 이동·위치 확인한 뒤 존 밖에서 정지 상태를 보고해야 해제된다.
맵 변경만으로 퇴장했다고 추정하지 않는다. 탑승 전에 취소가 확인된 도착 층 예약은 반납한다.
교통 예약·대기 작업이 있으면 맵 활성화·구역/설비 편집과 해당 로봇의 등록 해제·다른 맵 재배정을 차단한다.
예약이 남은 종료 작업도 삭제할 수 없다.

## API와 저장

기존 맵 구역 API에 `type=occupancy`, `gates=[{gate_id, wait:{x,y,theta}, exit:{x,y,theta}}]`를 추가했다.
선택 필드 `rotation`은 중심 기준 회전 각도(도)이며 기본값은 0이다. `x/y`는 회전 전 좌상단 좌표다.
점유 존은 `annotations.json`과 맵 버전 해시에 포함하고 정적 PNG에는 굽지 않는다.

| API | 용도 |
|---|---|
| `GET /api/v1/sites/{site}/maps/{map}/traffic` | 정원, 예약, 존 상태, 대기 작업 조회 |
| `PUT /api/v1/sites/{site}/maps/{map}/traffic` | `{"max_moving_robots": 2}` 설정. `null`은 무제한 |

`FMS_DATA_ROOT/traffic.json`에 정원과 예약을 원자적으로 저장한다. 작업 파일의 `traffic`에는
삽입 노드·원래 명령 대응·존 통과 순서를 저장한다. 단일 FMS 프로세스에서 코디네이터 락을 공유한다.

로봇의 `State.traffic_control=true`는 지원 여부다. `OrderNode.allowed_zone_ids`는 해당 노드로 가는
구간에서 허가한 존 목록이다. 목록에 없는 존은 재탐색·동적 장애물 회피에서도 막는다.
점유 존 맵에서는 정적 맵만 보는 PSO 다듬기를 사용하지 않는다.

존 밖의 로봇 간 교차·마주침·충돌 회피와 자동 교착 해소는 제공하지 않는다.
각 로봇의 물리 월드는 서로 독립적이므로 위험 공간은 빠짐없이 존에 포함해야 한다.

검증 명령은 **리포 루트**에서 실행한다. 물리 시험은 자체 브로커 18851과 임시 데이터만 사용한다.

```bash
make
.venv/bin/python -m pytest fms_server/tests/ -q
.venv/bin/python tools/physics_test.py traffic traffic-rotated
```

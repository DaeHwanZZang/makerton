# 알려진 문제와 제약

[프로젝트 시작 안내](../README.md) · [FMS](../fms_server/README.md) · [로봇](robot-client.md)

현재 코드와 기존 재현 기록을 기준으로 정리했다. 성능·오차 수치는 개발 당시의 관측값이다.

## 경로와 다중 로봇

- 동적 장애물은 센서 범위 안에서만 인식한다. 두 갈림길이 모두 막히면 과거 장애물을 기억하지 못해 경로를 번갈아 고르는 현상이 남아 있다. 장애물 기억과 시간 감쇠가 필요하다.
- 로봇끼리 서로를 장애물로 인식하거나 물리 충돌을 계산하지 않는다. 로봇마다 별도 물리 월드를 사용한다.
- PSO 경로 다듬기는 위 두 문제를 해결하지 않는다. 경유점 개수와 최종 목표를 유지하는 정적 경로 보정이다.
- 맵별 이동 정원과 점유 존 통과 예약은 [교통 제어](traffic.md)를 따른다. 존 밖의 전체 경로 예약·자동 교착 해소와 충전 스케줄링은 제공하지 않는다. 존 내부 작업 목적지는 지원하지 않는다.

## 위치 추정과 물리

- 초기 위치 확인은 힌트 주변의 스캔 매칭이다. 힌트가 탐색 창 밖에 있거나 대칭 복도이면 실패하거나 잘못된 위치로 잡힐 수 있다.
- 추적 보정은 참 자세에 노이즈를 더한 가상 측정이다. 완전한 라이다 기반 온라인 위치 추정이나 IMU 모델은 아니다.
- 매우 낮은 마찰과 큰 가속 요구(예: 마찰 0.12 / 가속 3)는 회전 헌팅으로 거의 이동하지 못할 수 있다.
- 구형 바퀴의 접촉 때문에 제자리 회전량이 오도메트리와 다르다. 슬립·오도메트리 오차와 위치 추정 오차는 구분해서 확인해야 한다.
- 이상 궤적의 `rotate_step`에는 방향 부호 변경 시 각속도 반전과 목표 도달 시 급정지 문제가 남아 있다. 순수 운동학 분기의 hold 각속도와 theta도 같이 확인할 필요가 있다.

## FMS와 승강기

- 파일 저장소와 프로세스 내부 락을 쓰므로 다중 worker 운용을 지원하지 않는다.
- 로봇의 수신 여부가 불명확한 assigned 작업은 자동 재게시하지 않는다. 작업 중복을 피하기 위해 예약을 유지한다.
- 도킹·주차·구역 편집 시 실제 로봇 크기와 공간 여유는 사용자가 확인해야 한다. 맵 셀 검사만으로 도킹 접근 경로 전체를 보장하지 않는다.
- 승강기 실패·취소 후 칸 안의 로봇을 자동으로 구조하는 절차는 없다. 임대는 메모리 상태이며 서버 재시작 후 진행 작업이 다시 확보한다.
- 층별 문 방향이 다른 승강기는 현재 전진 탑승·후진 하차 방식으로 사용할 수 없다.
- 승강기 선택용 0.25 m 비교 격자는 로봇 폭을 반영한 실제 로봇 A*와 다르다.
- 승하차 중 사람·장애물과 승강기 안전 인터록은 구현하지 않았다.

## 설치와 도구

- MuJoCo 설치 스크립트의 Linux 실행은 미검증이다. 리포 위치를 옮기면 절대 rpath 때문에 C++ 바이너리를 다시 빌드한다.
- `send_order --path`는 `-`로 시작하는 토큰에서 경로 수집을 끝내므로 음수 좌표 경로 입력을 지원하지 않는다. MQTT Order 자체가 음수 좌표를 금지하는 것은 아니다.
- 생성 맵의 world (0,0)은 보통 UNKNOWN 여백이다. 시작점과 목적지가 FREE인지 확인한다.
- `maps/gui_map`은 수동 원점과 edits가 있으므로 재생성하지 않는다. `maps/test1`은 편집기에 필요한 이미지가 빠진 샘플이다.
- 오래된 주석의 `AMR_master`, `robot_new`, 상위 프로젝트의 “결정 4” 참조는 과거 이력이며 현재 실행 의존성을 뜻하지 않는다.

## 해결된 문제 기록

### 일시정지 후 작업 처음부터 재실행

기존 기록 기준 2026-09-10 수정된 문제다. A* 세그먼트에 노드별 경유점이 여러 개이면 진행 인덱스가
제대로 전진하지 않아 재개 시 첫 노드부터 계획했다. 현재는 `segment_wp_bounds_`로 지나온 노드를 추적하고
다음 미도달 노드부터 재계획한다. FATAL/ERROR 시 오더를 버리고 FMS 작업을 failed로 처리하는 규칙은 유지한다.
